# One time model — source investigation

2026-10-03. **IMPLEMENTATION_ONLY / IMPLEMENTED_UNVALIDATED.** Read-only investigation of the original user requirements, today's `DECISION_STATUS.md`, committed contracts and held consumer/export drafts. No code/Git/validation/provider changes. This is a proposal and evidence note, not a completed implementation or executed test result.

## Recommended user rule

**Dates mean the local dates displayed on the screen. Data appears when it was measured, even when Android delivers it later. A session groups that same data; it does not move it to another date.**

Resolve the chosen dates once to a half-open UTC window `[first local midnight, midnight after the last date)` using one captured zone. Reuse that window for preview, History, export and write admission. Never use receipt/import time as observation time, assume every day is 24 hours, or use a timestamp as unique identity. Preserve each source's ID, correction, ownership, count domain, recorded zone and consent independently. Midnight and a display-zone change are read selections, not reasons to create new stored groups or rewrite IDs.

For actual readings, select their retained observation timestamp. For a genuine aggregate or recorded gap, select the real intersecting interval and retain its full bounds; a displayed subset must not claim that the whole aggregate was measured inside it. Calculate a smaller number only when the source can actually prove it. Missing timing/coverage stays unknown or partial. This is one time model with truthful source data, not six user settings.

## Concrete current gaps and smallest repair

1. **Cross-midnight background radio is still broken below presentation.** Wi-Fi projector `:394–401` and Cell `:376–383` clip `coverageStartTimeMs` to the newest accepted reading's day, while keeping earlier child timestamps. Native entity validation enforces that clipped day (`AmbientWifiFacts.kt:124–129`, Cell equivalent). `RoomAmbientWifiRepository.kt:299,214–215` / Cell equivalents then reject an earlier child using that lower bound. `AmbientWifiFactDao.kt:43–45` / Cell equivalent cannot discover that parent for the earlier date. The key-only displayed-day probe can see the child but the qualified parent reader cannot return it. This needs a real mixed-midnight source/Room fixture; existing written day-window tests do not prove this chain.
2. **Do not solve that by daily storage repartition.** The smallest consistent representation is one existing purpose-owned delivery group with its true measured bounds and unchanged children, plus its existing recorded-zone/end-day metadata. New facts can stop clipping the true lower bound; existing clipped native facts need a bounded read interpretation using their retained elapsed interval and wall anchor, without mutating canonical checksums/IDs. Exact source/authority and child completeness still qualify native data. Parent discovery must conservatively include actual matching children, then qualify them in the same bounded snapshot. Correction, retention and erase must cover the actual earliest selected measurement, not only the newest header.
3. **Portable radio needs the same meaning.** `RoomAmbientWifiPortableTransfer.kt:86–93` / Cell uses ordinary newest-header reads. `PortableWifiSourceExporter.kt:288–304` / Cell selects those parents then emits every child. `RadioSourceFileV2.kt:47–50,84–87` enforces the clipped parent range. Reuse existing retained qualification and accurate bounds; do not invent new IDs, sign user files or emit inconsistent parent summaries after cutting children. Old format compatibility and exact subset membership are required before any changed file scope is selected.
4. **Finish the approved displayed-day consumers, then reuse their semantics.** `HistoryObservationWindow` already provides half-open instant selection; `SourceExportDates.kt` already provides DST-aware construction, interval overlap and uncertain-time predicates. Keep one narrowly shared set of predicates at an existing contract boundary; avoid a new calendar service/framework. `UnifiedHistoryRangeReader.kt:348–407,509–579` already separates displayed radio/Location days from source-qualified Steps windows. `UnifiedHistoryOrganizationSelection.kt:25–84` still excludes whole crossing Activity/Pressure/background-radio groups, so retrospective selection needs measurement/window selection through source-owned readers rather than header rejection. It must never prorate counts or grant session consent from an annotation interval.
5. **Apply one exact-session choice consistently.** Existing `CapturedRadioDateSelection.kt:103–137` implements the approved smart switch: actual observation/uncertainty or explicit gap must touch selected dates; On includes the complete source session and counts outside readings; Off excludes a crossing complete entry. The actual export dispatcher exposes it only for `RadioSourceExporter` (`ImportExportViewModel.kt:349–362`). Steps/Activity/Pressure typed readers independently export whole logical entries from overlapping headers (`PortableStepsRoomReader.kt:842–845`, `ActivityCapturedPortableTransfer.kt:1098–1118`, `PortablePressureRoomReader.kt:101–142`). They need coherent actual-measurement selection and honest expansion. LastSession must use exact organization membership, not a widened date search; incremental timestamps must remain restricted to formats that really support point deltas (`ExportPlanWorker.kt:281–287`).

## Decisions versus already approved execution

Already settled: UTC storage/local calendar display, individual radio reading dates, original IDs, honest gaps, session annotations, retrospective measurement subsets, optional enrichment, one chosen source format, and the smart across-date session switch. Shared bounded read semantics and endpoint wiring are execution of these decisions. No daily partition/digest/schema or provider change is needed just to group a screen by day.

One coherent user proposal still needs confirmation: **“Export selected dates” means selected measurements; the existing across-date switch optionally adds complete matching sessions for every source.** This would supersede the earlier radio Off rule that excludes a crossing entry, if Off instead keeps its in-date measurements. Do not silently change that settled rule. Existing typed files may require whole records/correction ancestry/count graphs; exact subset file membership and overlapping imports remain pending decisions in `DECISION_STATUS.md`. Explain only the user's choice—selected dates versus complete sessions—and handle immutable record dependencies internally with truthful expansion, never invisible scope widening.

The true cross-midnight native bounds/read-compatibility proposal also needs a concrete reviewed data-handling confirmation under AGENTS.md before changing existing validation. That is substantially smaller than repartitioning groups; no new table is implied. Replacing Pressure aggregates with every raw sample, or exposing per-event Activity data that is no longer retained, would be a separate storage change and is not needed for the shared calendar rule.

**Recommended next slice:** approve the single visible date/session rule; implement accurate radio measured bounds plus conservative child-based discovery and retained compatibility; author mixed-midnight/DST/travel/correction/deletion cases; then wire existing day/retrospective/export selectors. Preserve all saved IDs and source independence. All 25 full-chain prerequisites and the final convergence remain open.

## 2. One annotation table; acquisition owns lifecycle

The adversarial pass removes a second session state machine and the proposed foreign-organization synchronization protocol. A live/recorded session already exists as an authenticated logical acquisition identity. Its read adapter supplies the organizational interval and replacement-run grouping. Creating/ending acquisition remains the existing coordinator's responsibility; there is no extra OPEN/CLOSED organization transaction.

Add one organization_annotation table:

- Local UUID primary key, local optimistic edit revision, created/updated time.
- Optional unique tagged recording_adapter_key, such as native logical identity or legacy segment identity. It identifies an existing local recording; imported metadata cannot acquire a native link.
- Optional start/end overrides and saved display zone, optional trimmed name/activity-label reference (max200 Unicode characters), optional imported descriptive label. A free retrospective/imported annotation requires valid closed bounds. A linked recording without overrides derives its bounds and open/ended/clock-uncertain state from its existing acquisition lifecycle.
- Nullable bounded typed imported selectors (version1, at most1MiB/4096 logical entry-or-day identities, at most64 child groups), tagged source/origin/purpose. They select imported source entries, not individual observations. Do not duplicate source checksums, import outcomes, profile summaries or fact revisions here.
- A hidden flag is allowed only for adapter-backed suppression. Hidden overrides clear descriptive payload; they exist only while needed to prevent the underlying recording adapter reappearing.

Index visible bounds, the unique adapter key and local ID. Use existing source range discovery for linked rows with inherited bounds. No foreign UUID, foreign metadata revision/hash, bundle snapshot ID, lifecycle state enum or imported tombstone registry is added. A local edit revision protects concurrent UI edits; it is not a wire synchronization protocol.

Existing records remain virtual through the read adapter. Editing/hiding materializes an override; exporting does not write metadata or allocate a foreign identity. Suppress every adapter having an override/hidden row **before range filtering and candidate limiting**. Query its visible override at the effective edited bounds, even when the original recording bounds lie outside the requested range; never let the old adapter leak back. New retrospective/imported annotations are ordinary local rows. Imported selectors restrict that annotation to its listed source entries and their qualified corrections; coincident unrelated facts remain excluded. Source receipts/readers determine availability and partial state.

Repository operations stay small: create a closed local annotation, edit with expected local revision/data epoch, remove/hide, and read/observe through shared history. Writes check epoch/revision in one existing Room transaction. Live edit supports name/label only; it introduces no second live-state owner. Removing a referenced activity label clears its reference, not observations. Import creates a local copy and never updates an existing annotation from foreign metadata.

Evidence for reuse: DataImporter.kt:398–425 provides content-based job identity; :111–128,149–164 handles completed-job and successful-entry retries. The data model needs annotation identity, not another distributed identity protocol.

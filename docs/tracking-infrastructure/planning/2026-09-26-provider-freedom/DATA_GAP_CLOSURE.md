## 2. Organization record and old-history adapter

### Recommended record

Add one `organization_session` table, with no observation membership table:

- `organization_id` opaque stable string primary key; local new/live/retrospective records use UUID. `revision` positive optimistic-concurrency counter; `created_at_ms`, `updated_at_ms`; `state` OPEN/CLOSED/HIDDEN.
- `start_time_ms`, `end_time_exclusive_ms`, `display_zone_id` are nullable in storage only to permit payload-cleared HIDDEN fences and explicitly clock-uncertain legacy/live bounds. VALID visible rows require start and zone; VALID CLOSED requires end greater than start, OPEN has no end. `origin` is LIVE/RETROSPECTIVE/LEGACY_ADAPTER/IMPORTED_ORGANIZATION. Optional name (trimmed, max200 Unicode characters), optional existing SessionActivity reference, and optional imported descriptive label text (max200, never sensor classification).
- Optional `linked_logical_tracking_id`, permitted only for locally authenticated live/legacy acquisition. Imported metadata cannot set that link. Optional `legacy_adapter_key`, unique, suppresses duplicate adapter rows. Optional foreign portable organization identity, metadata revision/hash, bundle snapshot ID/checksum and import receipt for imported duplicate/conflict checking; these grant no runtime authority. Organization metadata identity and the exported data snapshot are separate domains.
- Nullable bounded `imported_selection_bindings` BLOB with explicit version1, max1MiB: up to64 child descriptors and4096 total **logical entry/day identities**, each tagged source/purpose/origin and child checksum/import receipt/outcome. This is a bundle membership list at source-entry granularity, not observation membership. Null means local dynamic interval composition; nonnull means an imported group resolves only the listed imported children and their qualified corrections. Missing/rejected children remain typed missing, never replaced by coincident local observations.
- `hidden` is represented by HIDDEN state. Hidden rows retain only stable identity, revision, origin/link needed to suppress resurrection and privacy boundary; clear name, label and user interval when they are no longer required. No mutable acquisition manifest is stored here.

Indices: `(state,start_time_ms,organization_id)`, `end_time_exclusive_ms`, unique nullable `legacy_adapter_key`, unique `(foreign_organization_id,bundle_snapshot_id)` where present, lookup of foreign identity/revision, and acquisition link. Foreign organization identity alone is not unique: explicitly imported different snapshots can be separate groups. A partial unique index over OPEN local LIVE rows enforces one current live organization. Its insert/close follows the same durable accepted live-intent transaction or named reconciliation receipt, never a UI-only “started” flag. Before acquisition acceptance, draft UI is not a saved live session. Failed startup can close the accepted attempt with no evidence; it is not a successful recording.

Deleting a SessionActivity definition sets the local reference null and does not delete observations or grouping. Imported descriptive labels remain local text until the user explicitly chooses a local label. No automatic taxonomy, tags framework or inferred activity is added.

### Read adapter rather than mass backfill

Keep existing recordings discoverable immediately through a read adapter: one virtual organization per authenticated native logical session, grouping its replacement runs; legacy recordings without logical authority remain one virtual entry per original legacy segment; imported source entries keep source-owned portable identities/origin. Stable adapter keys are tagged tuples such as `native-logical/<logicalId>` and `legacy-segment/<localId>`, not guessed equality across origin types. They are local keys; export derives portable opaque identities, never exports raw local database row IDs as global identity.

Only editing/removing an adapted item creates an organization override/suppression row with its adapter key. This avoids large speculative migration, duplicate old cards and rewriting source rows. No virtual row is emitted when a matching override or HIDDEN suppression exists. A modern live row's acquisition link suppresses its matching native adapter. An imported bundle's metadata links only its imported child identities and cannot suppress unrelated native recordings by matching text/time.

Portable identity is explicit: locally created UUID remains its export identity; virtual adapter export materializes a lightweight organization row with a UUID and unique adapter key **before** writing, without copying facts or changing acquisition. This small exception to edit-only materialization ensures repeated exports have stable identity without a new installation-namespace service or hashes of bare numeric row IDs. Store the export UUID when materializing, and never regenerate it on retry. Equality at a given organization revision compares only canonical organization metadata (name/label, saved bounds/state, zone and descriptive origin), excluding query-now, selected sources, child bytes/revisions, coverage and profile summaries. Those belong to a separately identified bundle snapshot. Different selected children or later corrections with unchanged organization metadata are valid new snapshots, not metadata conflicts. Reimport matching a local export UUID never overwrites that local row. Exact snapshot retry uses its receipt; a different snapshot or newer metadata is offered only as an explicitly previewed separate imported copy, with a new local UUID and descriptive foreign lineage. Same organization revision with different metadata, or same snapshot ID with different checksum, is a conflict and never auto-merges. This checks consistency, not cryptographic authorship of an unsigned file.

Concrete repository surface: `createRetrospective(validatedBounds,label,expectedDataEpoch)`, `update(id,expectedRevision,changes,expectedDataEpoch)`, `hide(id,expectedRevision,expectedDataEpoch)`, `observe(id)`, and bounded `readRange(request)`. Live create/close are coordinator-only operations linked to durable lifecycle acceptance. All writes check current deletion epoch plus optimistic revision inside one Room transaction. Hidden identity cannot be revived by a merge import; a deliberately requested separate copy is a new identity and still cannot resurrect erased child facts.

**Alternative:** eager backfill every old recording into the new table. It simplifies one reader but creates migration volume, idempotency and uncertain-origin problems without improving user behavior. Not recommended. Per-record memberships/frozen snapshots are also unnecessary for editable time intervals.

Existing reward/session metrics use **Recorded sessions**: authenticated logical capture identities with qualified captured evidence, replacement runs deduplicated. Organization creation/editing grants no XP.
- “Recording time” is the union of qualified acquisition intervals, not movement or exercise. Preserve existing effect eligibility/receipt revisions while changing misleading presentation. ## 5. Bounded shared range and action contract

Extend TrackingHistoryRepository with a source-aware `readRange/observeRange` request containing from/to, view zone, source set, explicit LOCAL/IMPORTED/BOTH origin filter, purpose filter and cursor. Defaults in general History are BOTH origins and all product purposes, CONTROL excluded. Source detail fixes its own source/purpose/origin. Organization contents use the same qualified readers, not timestamp-only raw DAO queries.

Recommended result: Content(rows, nextCursor, readSnapshot, coverage/completeness), Empty only when exact scanned scope is complete, or typed Unavailable/DependencyOverflow/StaleSnapshot. One row identity is tagged native logical, legacy physical, imported source entry, ambient structural day or organization. Mixed source sets remain source-set rows, not a fabricated Physical Trip. Source-specific partial/error state can coexist with usable sibling sections; shared authority corruption still invalidates the common snapshot.

Reuse current page cap100; bound candidate discovery to100 per origin/source stream per page (plus one key-only lookahead to establish whether that stream has more), complete logical-member loads to existing256 (stricter source bounds such as Pressure64 still win), and existing fact budgets (Pressure8192, source-specific radio limits) rather than lifting them. Choose **consumed-frontier cursors, with no pending-candidate payload carried between calls**:

- Every stream discovers canonical entry/group representatives ordered by the final strict key `(startTime DESC, originTag ASC, stableId ASC)`. A logical group has one stable representative/key under the frozen snapshot, independent of which replacement run or source first found it. Fetching a member as a qualification dependency is not consuming its representative. Physical members of an authenticated logical replacement group are suppressed by the same snapshot rule on every page, not merely because that group's row happened to be emitted on the current page.
- Merge the stream heads in this final order. Fully authenticate each head's group before emitting its representative or definitively rejecting/suppressing it. Consume all equal canonical representative heads together across streams; emit that group once. Do not reorder a group after cursor advancement by substituting a later-loaded member's timestamp. An unresolved group remains at the frontier with a typed failure/overflow; it is not silently skipped.
- Stop after100 emitted rows, or earlier when a stream's fetched buffer is exhausted but its lookahead says more candidates remain: unseen candidates in that stream might precede other buffered heads. Return a bounded continuation rather than emitting past that unknown frontier or refilling until enough rows appear. A definitively exhausted stream does not block the remaining streams.
- Advance each stream cursor only through its contiguous candidates **consumed by this merged frontier**, including qualified rejected/suppressed candidates reached before the stop. Fetched, prequalified or dependency-loaded candidates beyond that frontier remain unconsumed and are fetched again next call. In particular, fetching100 from each of two streams and emitting100 in total cannot advance both cursors past their100 fetched rows. A stream with no consumed candidate retains its prior cursor.

Cursor carries those per-stream consumed keys, upper admission/import high-waters, range/filter hash and privacy/retention/organization selection revisions. New appends above the frozen high-water wait for refresh rather than constantly invalidating old-history browsing. Correction/replacement of a selected existing lineage, deletion or changed retention invalidates the cursor; return StaleSnapshot/restart, never a mixed-page total. A page containing only rejected/suppressed candidates can be empty with a next cursor. Cursor input is untrusted and reauthenticated; no long-held Room transaction spans UI pages. Exact snapshot membership and strict tie order are prerequisites for this paging contract, not inferred from a raw recent-page merge.

Calendar/timeline pass the requested old-day/month interval; they never filter a recent100 page. Month view uses bounded range discovery and marks incomplete months explicitly if a budget is reached; it must not paint unscanned days as empty. Continue paging on user/visible demand. A day click runs its own exact day range. Aggregate totals are shown only when their qualifying scope is complete or explicitly a known subtotal. This avoids a new day warehouse and per-list-row proof fanout.

Action selectors add Steps and Pressure to existing Activity/Wi-Fi/Cell. Each selector is tagged source, origin, purpose, stable logical/entry identity, supported scope, relevant revision and read snapshot. Navigation may persist the stable selection descriptor; before export/erase re-read it and mint fresh source-owned authority. A cached UI token cannot carry permission across process death, correction, retention or deletion. Queries never acquire providers, repair projections or insert summaries.

Last-successful UI rows may survive a transient IO error only while their exact retained authority remains valid, visibly marked stale. Privacy/deletion/retention or proof invalidation clears/requalifies payload and disables actions; generic error caching cannot continue displaying erased observations. This rule applies to maps, widgets and organization details as well as recent history.

Pressure's full vertical is required for the six-source gate: source-aware date/day/range discovery, hPa windows/coverage detail, exact selected native/imported export and erase, and existing effect constraints. Reuse `PressureHistoryBatchReader` and the LIFECYCLE exact lineage/retention authenticator in a fixed-count batch; preserve original writer/manifest binding rather than require today's writer owner. Authenticate every retained correction predecessor required by the source before selecting the current revision.

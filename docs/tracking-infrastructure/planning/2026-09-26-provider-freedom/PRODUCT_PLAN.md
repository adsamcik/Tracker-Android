## 1. Product contract and scope

The user's confirmed model is sufficient to settle the organizing principle: users choose what to record; each selected, supported, permitted source works independently; available evidence determines available features. Manual and automatic sessions share the engine, and separately consented ambient collection stays sessionless. Automatic control prerequisites are explicit and separate from captured sources. Enrichment reads compatible retained evidence without causing acquisition.

The minimum useful experience is the existing Settings -> Start -> live status -> recent/history -> detail -> export/delete flow, plus the same truthful state through widgets, notifications, and shortcuts. Keep the current Dashboard, Tracker screen, History tabs, source cards, typed readers, opaque selection handoff, and purpose pipeline. Do not create another generalized brain, a universal day platform, a separate flow for every capture mode, or a redesign of navigation.

The acceptance matrix below covers all 15 nonempty combinations of Location, Steps, Wi-Fi, and Cell plus empty selection, across manual/automatic/sessionless ambient where implemented and approved. Activity and Pressure remain compatibility/regression cases because the existing common history and live contracts include them. Completing newly invented ambient Activity/Pressure products is outside this MVP.

The already-approved default-off passive/opportunistic ambient Location baseline is required: `WORK_ITEMS.json:2541` (`WI-LOCATION-AMBIENT-PRODUCT-001`) explicitly requires separate consent, the protected sole writer, truthful point coverage, retention, export, deletion and explanation. `WORK_ITEM_TRACKING.md:114` preserves this independently of expanded ambient decisions. Current containment is an implementation gap, not a scope exception. Only products beyond passive/opportunistic points remain optional (`WORK_ITEMS.json:5923`, `WI-DEC-AMBIENT-LOCATION-001`).

High-level approval does **not** select an Activity CONTROL retention lifetime, new ambient Location storage/UX details, a new geographic accuracy threshold, a 30-second UI polling cadence, a 24-hour dashboard window, or a cross-midnight session-count rule. Those concrete choices are enumerated below for one batched approval. Reasking whether the passive baseline belongs in scope is unnecessary; deferring it would instead require explicit user authorization and a narrowed completion claim.

You must follow the "Thorough Investigation Protocol" before starting any complex task or implementation.

# Thorough Investigation Protocol

When a user asks for a change, do NOT jump straight to coding. You must:

1.  **Search Globally**: Do not assume code location. Review the file structure using `list_dir` or `view_file_outline` first. Use `grep_search` on the root directory (`g:\Github\Tracker-Android`) to find all occurrences of relevant terms, class names, and resource keys.
2.  **Analyze Usages**:
    *   Check for **Inheritors** and **Overrides** of classes/functions you plan to change.
    *   Check for **Call Sites** in all modules (app, sbase, sutils, feature modules).
3.  **Check Resources & Manifests**:
    *   If changing resources, check `AndroidManifest.xml` and Layouts/Compose references.
    *   Verify `build.gradle.kts` in the target module AND root/buildSrc for dependency management.
4.  **Verify Tests**:
    *   Search for existing tests (`*Test.kt`).
    *   Check `unit_test_failure_log.txt` for known issues.

# Implementation Rules

1.  **Threading & StrictMode**:
    *   **NEVER** perform disk I/O or database operations on the `Main` thread.
    *   Use `Dispatchers.IO` for blocking operations.
    *   Use `Lazy` initialization for heavy objects in ViewModels/Repositories.
2.  **Modularization & Visibility**:
    *   Check module boundaries. `api` exposes dependencies, `implementation` hides them.
    *   Use `internal` visibility by default for new classes within a module unless they must be public.
3.  **Architecture (MVVM)**:
    *   **UI (Compose)** observed `ViewModel` state.
    *   **ViewModel** interacts with **Repositories** (or UseCases).
    *   **Repositories** manage data sources (DB, API, Preferences).
    *   Do NOT bypass layers (e.g., UI calling DB directly).
4.  **UI & Compose**:
    *   When creating/modifying UI, check for `@Preview` annotations.
    *   Ensure creating a "Preview" or "Fake" implementation for data sources to allow UI testing without a full backend.

If you are unsure about the scope, run the workflow: `.agent/workflows/thorough_investigation.md`

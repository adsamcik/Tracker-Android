# Copilot instructions

Follow the repository-wide source of truth in `AGENTS.md`.

Before changing code, use the search and file-inspection capabilities available in the current
environment to inspect the module graph, relevant build files, call sites, resources, manifests,
and tests. Search from the repository root with repository-relative paths; do not assume a drive,
checkout path, tool command, model identifier, or agent-dispatch API.

When QC or emulator testing is requested, follow `.github/skills/android-qc/SKILL.md`. Discover the
available device-control and evaluator capabilities first. Use one representative emulator/API
configuration, and use one evaluator when that is all the environment provides. Treat evaluator
output as hypotheses until it is supported by code, screenshots or element evidence, logs, or an
interactive reproduction.

Investigate the root cause of reported problems before editing. If current behavior is intentional
and better supported than the reported expectation, preserve it and explain the evidence.
